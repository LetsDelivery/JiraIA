# Etapa 6b — Servidor MCP

A segunda parte da Etapa 6 (escopo-mvp 4.9). Decisões de Stênio em 2026-10-19, no ADR-0020. Outras
plataformas — um assistente próprio, o Claude, as rotinas do repositório de produto — conectam no JiraIA
por MCP, leem e pedem mudanças. Toda mudança é uma proposta (Etapa 6a).

## Entrega

| O quê | O que existe |
|---|---|
| Endereço | `POST /work/v1/mcp`, com `Authorization: Bearer jia_…`. Transporte *Streamable HTTP* do MCP, sem sessão: uma mensagem por requisição, resposta em JSON. Versões `2025-11-25`, `2025-06-18` e `2025-03-26` |
| Leitura | `list_spaces`, `describe_space` (estados, tipos e campos, com ids), `search` (cards e páginas), `query_cards` (o filtro estruturado, equivalente da JQL), `get_card` (com comentários e vínculos), `get_page`, `list_members`, `list_proposals`, `get_proposal` |
| Escrita | Mudou na Etapa 6d (ADR-0022): uma pessoa escreve na hora (`create_card`, `update_card`, `comment_on_card`, `link_cards`); uma conta de serviço propõe (`propose_changes`, `withdraw_proposal`) |
| Permissões | As do dono do token, como no painel |
| Erros | Card inexistente, recusa ou argumento inválido voltam como erro da ferramenta, com uma frase que o modelo usa para corrigir. Ferramenta ou método desconhecido é erro JSON-RPC |
| Registro | Cada chamada de ferramenta fica no log com o nome da ferramenta e o membro |

## Como conectar (até a Etapa 6c)

1. **Integrações → Nova conta de serviço** (por exemplo, "Assistente"), e um token para ela.
2. Na plataforma, um servidor MCP remoto (HTTP) com a URL `https://<api>/work/v1/mcp` e o cabeçalho
   `Authorization: Bearer <token>`. No Claude Code:
   `claude mcp add --transport http jiraia https://<api>/work/v1/mcp --header "Authorization: Bearer <token>"`.
3. A conta de serviço lê o que a organização lê. Para que ela leia o resto, dê papel em **Pessoas e papéis**.

## Fica para depois

- Conectar sem token, por OAuth com login Google e consentimento (Etapa 6c).
- Respostas em *stream* (SSE), notificações de progresso, recursos e prompts.
- Propostas de páginas.

## Demonstração

`bun run up`, conta de serviço e token como acima:

```
curl -X POST localhost:8280/work/v1/mcp -H "Authorization: Bearer <token>" -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"comment_on_card","arguments":{"card":"PRD-6","body":"Resumo"}}}'
```

A resposta traz `proposalId` e `status: pending`; **Propostas** mostra 1 para o admin.

Testes que cobrem a etapa:
- `mcp.integration.test.ts`: o cliente oficial do SDK conecta, lista, lê, propõe e lê a decisão; regras do
  transporte (202, 405, versão desconhecida, lote, sem token);
- `protocol.unit.test.ts`.

**Pronto quando:** um cliente MCP qualquer conecta com um token, lê cards e páginas com as permissões do
dono do token e pede mudanças que só acontecem quando uma pessoa aprova.

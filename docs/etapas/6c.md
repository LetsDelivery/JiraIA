# Etapa 6c — Conectar aplicativos por OAuth

A terceira parte da Etapa 6. Decisões de Stênio em 2026-10-19, no ADR-0021. Conectar uma plataforma ao
JiraIA deixa de pedir token: a pessoa cola o endereço (ou clica em "conectar"), entra com o Google e
permite. O aplicativo age **como a pessoa que permitiu** — a forma mudou na Etapa 6d (ADR-0022).

## Entrega

| O quê | O que existe |
|---|---|
| Descoberta | O MCP responde 401 com `WWW-Authenticate` apontando para `/.well-known/oauth-protected-resource`, que aponta para `/.well-known/oauth-authorization-server`. É o que os clientes MCP (Claude, Claude Code e outros) leem sozinhos |
| Registro | O aplicativo se registra sozinho (`POST /oauth/register`), com nome e endereço de volta (`https`, ou `http` em localhost) |
| Consentimento | Página **Conectar aplicativo** (`/oauth/autorizar`) no painel, atrás do login Google. Mostra o nome do aplicativo, para onde a pessoa volta e o que ele pode fazer: ler o que ela lê e propor mudanças que uma pessoa aprova. **Permitir** ou **Cancelar**. Quem chega deslogado entra e volta para a página |
| Tokens | Acesso por 1 hora e renovação por 30 dias, trocada a cada uso (PKCE S256 sempre). Um token de renovação usado duas vezes encerra a conexão. O token só abre o MCP |
| Como a pessoa | Escreve com as permissões dela, na hora; o histórico mostra "via Minha Plataforma" (Etapa 6d) |
| Desconectar | **Meu perfil → Aplicativos conectados**: o aplicativo, para onde volta, desde quando, último uso e **Desconectar**, que encerra os tokens na hora |

API: `/.well-known/oauth-protected-resource`, `/.well-known/oauth-authorization-server`,
`/oauth/register`, `/oauth/token`, `/oauth/consent`, `/oauth/authorizations`, `/me/connections`.

Infra: rotas sem autorizador para `/.well-known/{proxy+}`, `/oauth/register` e `/oauth/token`; parâmetro
`ApiUrl` (endereço público da API; vazio usa o Host da requisição). Migração `0014_oauth`.

## Como conectar

No aplicativo, adicione um servidor MCP remoto com a URL `https://<api>/v1/mcp` (localmente,
`http://localhost:8280/work/v1/mcp`) e nada mais. O aplicativo abre o JiraIA para você permitir.

O token de conta de serviço da Etapa 6b continua funcionando para rotinas sem pessoa por trás.

## Fica para depois

- Registro por documento de metadados do cliente (`client_id` como URL).
- Limite de requisições no registro e no token.

## Demonstração

`bun run up`, e no Claude Code:
`claude mcp add --transport http jiraia http://localhost:8280/work/v1/mcp`, depois `/mcp` → autenticar. O
navegador abre **Conectar aplicativo**; **Permitir** volta para o Claude Code, que lista as ferramentas.

Testes que cobrem a etapa:
- `oauth.integration.test.ts`: o cliente oficial do SDK descobre, registra, manda a pessoa ao
  consentimento e conecta; código de uso único com PKCE, rotação, reuso, expiração, desconexão, token que
  só abre o MCP, propostas por pessoa e o aviso de decisão;
- `oauth.unit.test.ts`, `router.unit.test.ts`;
- `bun run web:e2e`: `oauth.spec.ts`.

**Pronto quando:** uma pessoa sem conhecimento técnico conecta um aplicativo ao JiraIA só com a URL, o
login Google e um clique, e o desconecta pelo perfil.

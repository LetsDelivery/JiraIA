# Etapa 9 — GitHub

Rascunho (2026-10-29). Pedido do Stênio: o time cria a branch com a chave do card e o JiraIA passa a
mostrar o que acontece com ela, inclusive o merge. A única mudança automática é o card ir para revisão
quando o pull request é mergeado. Decisão no ADR-0038; antes estava fora do MVP.

## Entrega

| O quê | O que existe |
|---|---|
| Conexão | Página **GitHub** (menu da conta). Um administrador da organização clica em **Instalar no GitHub**, instala o app em todos os repositórios da LetsDelivery e volta para `/github/conectar`. A API confere a instalação no GitHub como o app antes de guardar. Desconectar fica auditado; desinstalar no GitHub também desconecta |
| Entregas | `POST /github/events`, fora do roteador, como o Slack: assinatura `X-Hub-Signature-256` conferida primeiro; entrega repetida (`X-GitHub-Delivery`) não age de novo. Com o banco pausado, a entrega espera ele acordar (o GitHub não reenvia sozinho) |
| Vínculo | A chave do card no nome da branch ou no título do PR liga os dois. Branch criada e apagada; PR aberto, rascunho, atualizado, fechado e mergeado; revisão (aprovado, mudanças pedidas); checks (rodando, ok, falharam) |
| Card | Seção **Desenvolvimento**: PRs com estado, revisão e checks, depois as branches, cada um com link para o GitHub. Botão **Copiar nome da branch** (`feat/TEC-1343-titulo`, `fix/` para tipo com cara de bug) |
| Merge | Em **Configurações › Fluxo**, "Quando um pull request é mergeado": o estado para onde o card vai. Só merge na branch principal do repositório; card concluído ou cancelado não sai do lugar. Quem move é o agente **GitHub**, e as automações do espaço reagem |

Migração `0030_github-integration` (`github_installations`, `github_deliveries`, `card_dev_links`,
`spaces.merged_state_id`).

API: `/integrations/github` (GET, DELETE), `/integrations/github/install`,
`/integrations/github/complete`, `/cards/{cardId}/development`, `PATCH /spaces/{id}` com
`mergedStateId`.

## Para ligar em dev e prd (pendente)

1. Criar o GitHub App na organização LetsDelivery (precisa de um dono da organização). Permissões só
   de leitura: *Contents*, *Pull requests*, *Checks*, *Metadata*. Eventos: *Create*, *Delete*,
   *Pull request*, *Pull request review*, *Check suite*. Webhook URL:
   `https://<domínio do painel>/api/work/github/events`. Setup URL: `https://<domínio do painel>/github/conectar`,
   com "Redirect on update" marcado.
2. Guardar a chave privada e o webhook secret no segredo `jiraia/github` (`private_key`,
   `webhook_secret`) da conta.
3. Preencher `GitHubAppId` e `GitHubAppSlug` no `Mappings` do `template.yml` e implantar.
4. Instalar pela página GitHub do painel. Se quem conecta não é dono da organização no GitHub, um dono
   instala direto no GitHub (`github.com/apps/<slug>` › Install › All repositories) e o admin clica em
   **Conectar a instalação existente** na página GitHub do painel.

Dev ligado em 2026-10-29: App `jiraia-lets-dev` (5532897), instalação 176688050 em todos os 73
repositórios da LetsDelivery. Prd: App `jiraia-lets-prd` (5532923), segredo gravado, falta instalar.

## Demonstração

Localmente, sem app real:

    bun run up
    # Painel → GitHub → Instalar; ou completar com installation_id=1 em /github/conectar
    # TEC › Configurações › Fluxo → "Quando um pull request é mergeado" = REVISAR
    bun run local:github -- branch feat/TEC-1343-migrar-webhook
    bun run local:github -- pr open 41 feat/TEC-1343-migrar-webhook "TEC-1343 Migrar webhook"
    bun run local:github -- review 41 approved
    bun run local:github -- checks feat/TEC-1343-migrar-webhook success
    bun run local:github -- pr merge 41 feat/TEC-1343-migrar-webhook "TEC-1343 Migrar webhook"

O TEC-1343 sai de EM PROGRESSO para REVISAR (no board do TEC, REVISAR fica dentro da coluna EM
PROGRESSO — ADR-0037) e a seção Desenvolvimento mostra o PR mergeado, aprovado, com checks ok, e a
branch.

Testes: `github.integration.test.ts` (instalação, assinatura, entregas repetidas, branch, PR, revisão,
checks, merge e as regras de quando não move), `github.unit.test.ts`, o roteamento em
`lambda.unit.test.ts`, e no painel `github.test.ts`.

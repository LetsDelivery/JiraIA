# Etapa 6d — O assistente age como a pessoa

Uma correção de rumo da Etapa 6, decidida por Stênio em 2026-10-19 (ADR-0022). Como no Jira com o
Claude: depois de conectar, o assistente (por exemplo, a Laís) cria e altera cards **como a pessoa**,
na hora, sem aprovação. A pessoa já decidiu quando pediu.

## Entrega

| O quê | O que existe |
|---|---|
| Escrita direta | Pelo MCP, uma pessoa (conectada por OAuth ou com token pessoal) tem `create_card`, `update_card` (inclusive mudar o estado), `comment_on_card` e `link_cards`. Respondem com o card e o link para abri-lo |
| Permissões | As da pessoa: escreve onde ela escreve e em nenhum outro lugar. Pessoa desativada derruba o token |
| Histórico | Cada mudança feita pelo aplicativo aparece como da pessoa, com a marca **via Laís** (coluna `audit_events.via`) |
| Consentimento | A página diz que o aplicativo vai ler e escrever **como você**, e que o histórico mostra "via" ele |
| Propostas | Continuam, só para agentes autônomos: uma conta de serviço no MCP tem `propose_changes`, `list_proposals`, `get_proposal` e `withdraw_proposal` |
| Removido | O agente por aplicativo, `onBehalfOf` nas propostas e o aviso *Decisões sobre propostas* |

Migração `0015_application-acts-as-person`.

## Demonstração

Conecte o Claude Code (Etapa 6c) e peça: "crie uma tarefa no PRD: revisar contrato Acme, prioridade
alta". O card aparece no board na hora, com você como relator; no histórico, "via Claude Code".

Testes que cobrem a etapa:
- `mcp.integration.test.ts`: pessoa escreve na hora dentro dos papéis dela; agente só propõe;
- `oauth.integration.test.ts`: o SDK conecta e comenta como Ana, com `via`; só escreve onde Ana
  escreve; pessoa desativada derruba o token;
- `via.unit.test.ts`; `bun run web:e2e`: `oauth.spec.ts` (histórico com "via").

**Pronto quando:** a pessoa pede ao assistente e o card existe, em nome dela, sem ninguém aprovar.

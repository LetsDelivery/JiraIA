# Etapa 2 — Cards e board

## Entrega

| Item do escopo | O que existe |
|---|---|
| 2.1 Tipos de card por espaço | Tabela `card_types`; todo espaço nasce com os tipos do seu tipo de espaço |
| 2.2 Fluxo configurável | Estados por espaço com nome livre (emoji incluso) e grupo; criar, renomear, reagrupar, reordenar e excluir (movendo os cards) em **Configurar fluxo** |
| 2.3 Transições livres | Qualquer estado para qualquer estado |
| 2.4 Campos padrão | Título, descrição (texto), responsável, relator, prioridade em 5 níveis, labels, data limite, estimativa P/M/G |
| 2.5 Campos customizados | Texto, número, data, seleção única, seleção múltipla, pessoa e URL, por espaço, restritos a tipos de card; editados em **Campos**. Excluir um campo tira o valor dos cards e deixa no histórico |
| 2.6 Subtarefas e hierarquia | Card pai (`parent_id`) e subtarefas criadas no detalhe; um card com subtarefas não sai do espaço sem elas |
| 2.7 Vínculos tipados | Relaciona, bloqueia / é bloqueado por, duplica, entrega / é entregue por, causa (incidente), entre cards de qualquer espaço; lidos dos dois lados |
| 2.8 Comentários | Menção a pessoas e agentes (`@` sugere, quem é mencionado passa a observar), reações e edição pelo autor, com o texto anterior no histórico |
| 2.9 Anexos | Upload por URL pré-assinada do S3 (`AttachmentsBucket`), arrastar, escolher ou colar imagem no comentário; prévia de imagem. No local, o disco faz o papel do S3 (`infra/local/files.ts`) |
| 2.10 Histórico campo a campo | Cada alteração vira evento de auditoria, mostrado no detalhe do card |
| 2.11 Observadores | Observar e deixar de observar; relator, responsável, quem comenta e quem é mencionado passam a observar |
| 2.14 Mover entre espaços | O card ganha chave nova no destino, guarda o histórico, e a chave antiga continua abrindo ele (`card_key_aliases`) |
| 3.1 Board kanban | Colunas por estado, arrastar e soltar entre e dentro das colunas, criação rápida por coluna, busca, "Só os meus" e **raias** por responsável, prioridade, tipo ou card pai — soltar em outra raia muda esse campo |
| 3.2 Lista | Aba **Lista**: tabela com colunas escolhidas por quem vê (padrão e customizadas), ordenável por qualquer uma |
| 3.3 Backlog | Aba **Backlog**: cards abertos numa ordem manual própria (`backlog_rank`), arrastando |
| Numeração | `KEY-n` por espaço, atômica (sem número repetido com criações simultâneas) |
| Papéis | Leitor lê e comenta; convidado vê só os cards em que está envolvido |
| Seletor de data | Próprio (`ui/date-picker.ts`), no lugar do nativo do navegador |

Espaços de exemplo no seed, com os fluxos reais do Jira (`backlog/fluxo-jira.md`): **PRD · Discovery
Board** (10 estados, de Backlog a Bloqueado, com oportunidades de exemplo), **REQ · Requisições** e
**TEC · Delivery Board**.

## Demonstração

`bun run up`, entrar como `admin@uselets.com` e, no PRD, operar um card de ponta a ponta: mover no board,
abrir, preencher campos padrão e customizados, criar subtarefa, vincular a um card do TEC, comentar
mencionando a Ana, anexar um arquivo, mover para outro espaço e abrir pela chave antiga — tudo no
histórico. `bun run web:e2e` percorre o mesmo caminho (`playwright/e2e/board.spec.ts` e `cards.spec.ts`).

**Pronto quando** (do prompt de construção): dá para recriar o fluxo do PRD — feito no seed — e operar
um card de ponta a ponta com histórico completo.
